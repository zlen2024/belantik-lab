# Critic bebas: pilot TWSI pair ranking

21 November 2026. GPT-6.2 Sol medium menyemak run `dc05b25eaf7c4583b4478bc734a27ebe`, code/protocol snapshots, empat hash split, checkpoint awal, dan hash dataset asal. Recomputasi NumPy float64 secara bebas bagi semua enam checkpoint menghasilkan metrik train, validation, context-removed dan context-shuffled yang sama dalam `1e-12`. Tiada hash ayat atau pasangan penuh merentasi split. Ketepatan log menunjukkan ini implementasi eksperimen yang ditulis, bukan bukti label membawa makna yang model lihat.

Experiment critique: 522/2,184 cue validation ialah `the`, dengan `of` 128 dan `a` 116. Pilihan cue ialah perkataan berdekatan pertama yang sesuai, sedangkan preference diberikan pada ayat penuh. Filter membuang 185 input visible yang bercanggah menggunakan semua label TWSI train sebelum split; ia menjadikan task lebih mudah dan menghalang tafsiran test bebas. Keadaan context-removed ialah perturbasi checkpoint yang sama, bukan baseline dilatih semula. Global shuffle sekali bukan null yang dipadankan dalam setiap target/pair. 121 reversal group mengandungi 413 baris dan 60 group tepat dua baris; group berkongsi target/sumber dan tidak iid.

Hypothesis critique: kedua-dua model boleh fit preference latihan, tetapi belum ada bukti stabil bahawa mereka menggunakan konteks sebenar dengan cara yang betul. Dalam analisis posthoc critic yang menukar cue secara boleh ditukar dalam setiap group sambil memegang skor tetap, expected strict successes bagi Ising ialah 5.98 / 4.78 / 5.45 berbanding observed 7 / 4 / 5; vector 11.92 / 7.32 / 9.58 berbanding 14 / 9 / 10. Ini jangkaan bersyarat terhadap skor dan kiraan group, bukan p-value atau penilaian bebas. Ising menghasilkan sebarang perubahan ranking dalam 23 / 17 / 22 group, vector dalam 48 / 41 / 39; perbezaan strict count sebahagiannya berkait kekerapan bertukar.

Raw R Ising bounded sedangkan vector dot product tidak bounded; tau sama `0.2` tidak menyamakan skala gradien atau pengoptimuman. Skor ranking boleh dilapor bersebelahan, tetapi perbandingan nilai loss dan keadilan optimization tidak terbukti. Track juga tiga had audit: jumlah threads diluluskan melalui environment, tidak dikuatkuasa oleh skrip; peak memory diperiksa setiap epoch tetapi angka tidak direkod; final checkpoint tidak mempunyai hash tersendiri dalam summary asal. Run asal menyimpan metrics dalam JSON, bukan semua sebagai native MLflow metrics. Vocab hash asal split dipaut menerusi data run tetapi tidak dibanding secara explicit oleh pilot; critic mengesahkan hash checkpoint/pretraining, dan tiada mismatch ditemui.

Selepas review, native MLflow metrics untuk tiga skor penting setiap seed serta SHA-256 setiap final checkpoint ditambah secara posthoc sebagai tags. Hash posthoc membantu semakan masa depan tetapi tidak membuktikan checkpoint itu telah dibekukan sebelum analisis. Environment yang dihantar menetapkan `OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS` dan `MKL_NUM_THREADS` kepada 4, serta JAX CPU; script sendiri tidak menguatkuasakan thread count.

Lean 4.36.0 / Mathlib `fc4f59e577feb1a4956671bc04ac18aaaf8cd842`, `lake env lean --stdin`, membuktikan ranking dengan margin tetap tidak boleh memenuhi kedua-dua arah preference dan pemerhatian konteks sama memberi skor sama untuk scorer deterministik. Kedua-duanya menggunakan `propext`, `Classical.choice`, `Quot.sound`, tanpa `sorryAx`. Ia tidak membuktikan loss stochastic, implementasi training, atau makna bahasa.

Next: bina subset yang konteks kelihatan memang menyokong preference dan sumbernya berasingan; gunakan perbandingan cue yang dipadankan dalam `(target,pair)`, control context-only dan baseline cue-free yang dilatih sendiri. Jangan terus menambah epoch atau membuat kesimpulan penggantian embedding berdasarkan data ini. Gaussian kekal comparator klasik berasingan yang perlu implementasi joint pada input sama; sense-region occupancy dan THRML parity kekal gates lain.
