# TWSI train-only connected split feasibility

Freeze before calculation, 21 November 2026. Build exploratory training/validation candidates only from `twsi_train.tsv` in the pinned ALaSca archive and existing 2,000-word vocabulary. Reuse exactly the corrected support audit filters and single immediate cue selection. Only score pairs explicitly present and unequal qualify; not-mentioned words are not negatives. A pair example is `(target, cue, candidate_a, candidate_b, preferred_a, sentence_hash)`, candidate IDs ordered alphabetically. Drop **all** examples whose identical model-visible `(target,cue,a,b)` has both preference directions; report how many are dropped. Deduplicate identical full rows.

Group examples with connected components: connect any examples sharing an exact casefold/whitespace sentence hash or the same `(target,a,b)` pair; transitivity is mandatory. Hash each component's sorted unique identifiers using SHA-256. Assign validation if the first 64 hash bits modulo 5 equals zero, otherwise training. This is deterministic, not stratified, and uses both directions only for data grouping, not for model selection. Inspect counts, target coverage, paired reversal group coverage and possible largest-component collapse. Verify no sentence or `(target,a,b)` crosses partitions. Report all target and context ambiguity and component size stats. Do not claim document or source disjointness, near-duplicate separation, or any natural-language accuracy. One cue may not justify full-sentence judgments. Do not train or open official dev/test for this audit.

Store dataset as local MLflow artifact containing IDs and sentence hashes only, plus vocabulary/data hashes, split rule, code, counts and limitations. `train` and `validation` are exploratory splits of the released TWSI train entry and cannot be final benchmark. Critic independently reviews grouping, potential leakage, split adequacy and alignment with both plans. Original ALaSca archive is CC BY-NC-SA 4.0; keep raw text out of Git and artifact payloads.
