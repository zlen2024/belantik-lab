# SWORDS shared-star repeated-development probe

22 November 2026. Exploratory diagnostic, not fresh validation or model training. The goal is to check whether placing all alternatives into one shared equilibrium, as in the original common-system plan, improves or degrades the existing trained Ising checkpoint readout and contextual sensitivity. This evaluates inference only; the checkpoints were trained on a different star topology. The official test remains closed.

Reuse exactly the 219-target input manifest, the 132 informative targets and human vote fractions from run `6bfbcadfb039410dbc206f963b50d2bf`; use the three frozen Ising seeds 17, 29, 43 and historical same-example vector and candidate-specific R predictions from `3878d013f4ae477f8af4c1e41cf1252b`. Verify manifest and checkpoint hashes. Generate all shared-star predictions before reading the saved labels for this script. This is not truly label-blind research: these development judgments and other readouts have already been repeatedly inspected.

For each target and seed place all candidate occurrences and original context occurrences together in a single system; use `ising_shared_correlations` with `g/(m+K)` per spoke and rank by raw target-candidate spin correlation. Control: replace every context occurrence with a uniform-unary dummy, retaining candidate set and normalization. Check zero-coupling product identity and finite bounds. Candidate count changes both graph and normalization; the readout is not a probability and is not directly the energy of a word.

Compute per-target AUC over exactly the existing strict >50% TRUE positive/other negative labels, and seed means. Report paired shared-minus-vector, shared-minus-candidate-specific and shared-minus-uniform differences with the existing source-proxy clustered 1,000 bootstrap draws, seed 23140, and repeat after excluding the already identified dominant source. Report per-seed and uncertainty; intervals are descriptive after repeated selection and source proxies may not be independent. Compare ranks to the candidate-specific scorer as a diagnostic. Preserve inputs, outputs, code, protocol and limitations in MLflow. Do not tune weights, model, candidate set, labels or training on these outcomes. No Gaussian joint comparator, THRML simulation or chip run is implied. Obtain independent critic after result.
