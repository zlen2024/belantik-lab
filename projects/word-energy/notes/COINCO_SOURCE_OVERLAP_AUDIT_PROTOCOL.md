# Posthoc CoInCo development source-overlap check

This is a **posthoc provenance audit**, written after a preliminary input-metadata check. Do not describe it as an analysis frozen before those preliminary source counts. It asks whether the SWORDS repository's `coinco_dev.json.gz` contains development source-file proxies absent from **all** SWORDS development contexts. It does not inspect judgments, score a model, construct a training set or access either benchmark test. A source-file match is evidence of shared source identifier, while a nonmatch does not rule out copied or near-duplicate text.

Pin CoInCo development source `https://raw.githubusercontent.com/p-lambda/swords/main/assets/parsed/coinco_dev.json.gz` SHA-256 `02180be2bf9e3b528682c659c5b410f3baa130dbc19a29be8755a0aae0d9cc5f` and the previously pinned SWORDS development file. The official repository describes both datasets and their provenance. Build CoInCo context source sets from `context.extra[*].masc.document_fn` and SWORDS sets from `context.extra.coinco_ids` using the prefix before the first colon. Mark missing or multi-source metadata, count unique source proxies and shared or non-shared contexts and targets, and list aggregate context/target counts for non-shared sources. No candidate labels or benchmark outputs participate. The JSON reader loads and then discards the serialized judgment mapping without using its values.

Log source hashes, counts, code/protocol and limitations in local MLflow. Keep downloaded source files Git-ignored. Because full SWORDS development and these source-level totals have already been examined, any subsequent training/evaluation split selected with this knowledge is developmental; plan a separate independently frozen evaluation. Exact source disjointness alone cannot establish no duplicated texts, lexical leakage, source dependence or semantic generalization. Ask critic to assess this provenance check together with crossed-support results.
