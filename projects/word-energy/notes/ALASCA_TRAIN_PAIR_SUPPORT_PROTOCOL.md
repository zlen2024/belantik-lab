# ALaSca training pair support audit

Before inspection: use only `alasca_datasets/alasca_train.tsv` from official ALaSca archive SHA-256 `0198abbe7f39ac6b5aa67ed6caf389795ad684cd9a2e0339ecc9e3640c55545b`. Do not open the archive's test or development entries. ALaSca labels are automatically generated silver scores, not human judgments; license is CC BY-NC-SA 4.0 as stated by publisher. This is an exploratory feasibility audit, not a model evaluation.

Use the existing WikiText2 2,000-word lookup from joint-context data. Retain only single-token ASCII alphabetic target, candidate and one immediate in-vocabulary context token; choose left then right, without skipping intervening tokens. For each row, form only candidate pairs whose two explicit silver scores are finite and unequal. Never interpret a missing candidate as a negative. Count candidate pairs and opposite-score reversal matches with the same target and candidate IDs and different chosen context IDs. Cap duplicate row-pair counting by reporting the number of distinct target/candidate/context combinations and target/candidate groups. Exact casefold tokenized sentence identity is an additional grouping proxy, not proof of document independence. Do not train, tune, inspect official test or treat silver preferences as verified human semantics. Archive does not guarantee document IDs, so document-disjoint splits must not be claimed. Store source hash, coverage counts, script and output in MLflow and obtain critic.
